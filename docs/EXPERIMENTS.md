# Experiments and figures

## RAVDESS configuration

`configs/ravdess.yaml` inherits `base.yaml`. Use `--set key=value` for explicit overrides:

```bash
python scripts/s3_train.py --config configs/ravdess.yaml --exp-name dp256 --validation-only --set model.d_p=256 train.lr=0.0001
```

The effective configuration is stored in the run directory and checkpoint. Changing the number of temporal segments requires rerunning the scan and visual/audio extraction in a new cache; changing `data.max_units` alone does not create new segment features.

The current defaults are 4 segments, `d=256`, `d_p=128`, `d_f=256`, 40 epochs, batch size 16, learning rate 1e−4 and validation selection by `seq_macro_f1`. These are the source defaults, not a claim that they generated every later manuscript table.

## Actor-independent CV and testing

| Outer fold | Test actors | Validation actors | Training actors |
| --- | --- | --- | --- |
| 0 | 01–04 | 21–22 | 05–20 |
| 1 | 05–08 | 21–22 | 01–04, 09–20 |
| 2 | 09–12 | 21–22 | 01–08, 13–20 |
| 3 | 13–16 | 21–22 | 01–12, 17–20 |
| 4 | 17–20 | 21–22 | 01–16 |

Actors 23–24 are reserved for the separate fixed-split test and are excluded from CV training. The fixed validation actors are also excluded from CV training. Fold summaries use population standard deviation (`ddof=0`), matching the retained source implementation.

```bash
python scripts/s3_train.py --config configs/ravdess.yaml --exp-name cv_seed42 --cv --seed 42 --validation-only
python scripts/evaluate.py --checkpoint runs/cv_seed42/fold0/best.pt --split test --out-dir runs/cv_seed42/fold0/test
```

Evaluate the remaining fold checkpoints similarly. The packaged evaluator reads the fold from `protocol.json`; an explicit conflicting `--fold` is rejected. When relocating a run, move `protocol.json` with the checkpoint. For older checkpoints without it, supply `--fold` explicitly.

`run_experiments.py` creates a sequential command plan and stops on a failed command. It is not a background queue manager and does not claim optimizer-state resume. Interrupted training should use a new run name. Existing completed checkpoints can always be tested independently.

## Ablations and parameter sweeps

The RAVDESS runner exposes `no_semantics`, `no_gate`, `no_mam`, `no_itac`, `no_itam`, `no_iipf`, `no_cmc`, `no_tpc`, `no_prr`, `no_proxy_weight`, `softmax`, `no_cal` and `main`.

```bash
python scripts/run_experiments.py --variants main no_iipf no_cmc no_tpc no_prr --seeds 42 43 44 --cv --validation-only --out-root runs/ablation
python scripts/run_experiments.py --grid configs/hparam_grid.example.yaml --seeds 42 --out-root runs/grid
python scripts/summarize_results.py --runs runs/grid --split validation --out tables/validation_grid.csv
```

Grid commands always add `--validation-only`. Select a configuration using validation results, then evaluate its checkpoint. The summarizer only collects completed metric files; it does not create missing values or select a winner based on test results.

The CMU runner supports the IIPF/head ablations plus `text_only`, `early_concat`, `mean_fusion`, `late_fusion` and `attention` baselines. These are implementation baselines, not substituted results for other named published systems.

```bash
python scripts/run_cmu.py --dataset mosi --seed 42 --stage train --variant no_cmc
python scripts/run_cmu.py --dataset mosi --seed 42 --stage evaluate --variant no_cmc
```

Run `--stage align` first for that seed. Fusion variants may share the same alignment within a seed. Different alignment/data configurations require a new `--out-dir`; changing them in an existing seed directory raises an error. For example, a new alignment sweep must not reuse an older learned feature cache.

## Figures

### Prediction-based panels

`plot_results.py` reads NPZ predictions generated by the packaged evaluators. `--level sequence` is the primary RAVDESS evaluation; use `--level unit` for CMU utterances. It outputs:

- Confusion counts and row-normalized matrix, calibration-bin data and reliability plot.
- Full risk–coverage curve with a stable tie order; error is the risk.
- Correct/incorrect uncertainty histograms and row-level source data.
- Optional training loss and validation macro-F1 curves.
- Recomputed classification metrics, a discrete mean AURC and trapezoid pAURC over [0.5, 1]. These integration conventions are explicitly named in the JSON.

The original evaluator also reports risk at five selected coverage levels. A sparse five-point integral is different from integrating the full curve and should be labeled separately.

### TMA and IIPF representations

Export complete, ordered features from a saved fixed-split run:

```bash
python scripts/s3b_extract_tma.py --config configs/ravdess.yaml --exp-name ravdess_main --split test --out-dir runs/ravdess_main/tma_test
python scripts/s3d_extract_iipf.py --config configs/ravdess.yaml --exp-name ravdess_main --split train --out-dir runs/ravdess_main/fusion_train
python scripts/s3d_extract_iipf.py --config configs/ravdess.yaml --exp-name ravdess_main --split val --out-dir runs/ravdess_main/fusion_val
python scripts/s3d_extract_iipf.py --config configs/ravdess.yaml --exp-name ravdess_main --split test --out-dir runs/ravdess_main/fusion_test
```

The IIPF exporter writes `fusion.csv`, the standalone evidence network and metadata. It is intended for evidential models; it checks agreement between full-model predictions and the exported head. Both exporters load checkpoint configuration and preserve the last incomplete batch.

The original manuscript-oriented plotting entry points are retained:

```bash
python scripts/s9_plot_multimodal_feature_landscape.py --features-root cache/ravdess/feats --output-dir figures/feature_landscape
python scripts/s10_plot_iipf_fusion_landscape.py --train-fusion runs/ravdess_main/fusion_train/fusion.csv --val-fusion runs/ravdess_main/fusion_val/fusion.csv --test-fusion runs/ravdess_main/fusion_test/fusion.csv --evidence-head runs/ravdess_main/fusion_test/evidence_net.pt --output-dir figures/fusion_landscape
```

These original scripts assume the 768-dimensional encoder features and the RAVDESS eight-class setting. In addition, the fusion landscape checks the original complete layout: 2,452 sequences, four units per sequence, 9,808 rows and 256 fusion dimensions. Use the generic prediction plots for subsets or other dimensions. The fusion landscape overlays upstream modality markers around fused coordinates; their offsets are for visibility and do not measure cross-modality distances. Class circles depict a quantile-based region in the embedding, not a confidence interval or decision boundary. The combined train/validation/test landscape is descriptive and must not be used for checkpoint or hyperparameter selection.

The waveform example can be produced with:

```bash
python scripts/s11_plot_ravdess_nyquist_waveform.py --video data/ravdess/Actor_18/01-01-03-02-02-01-18.mp4 --manifest cache/ravdess/manifest.csv --seq-id ravdess/Actor_18/01-01-03-02-02-01-18 --output-dir figures/waveform
```

The waveform script retains the original example-oriented output naming. The three original figure scripts can optionally use an external alignment checker with `--qa-tools-dir`; it is not required to render or save figures.

### Retained sequence aggregation / calibration tools

`s3e_seq_eval.py` exports evidence-sum and probability-mean sequence diagnostics; `s3f_seq_eval_summary.py`, `s8_ensemble_seeds.py` and `s9_posthoc_calibration.py` retain the historical multi-seed CSV workflow. Their expected layout is `runs/<exp-name>/seed<seed>/fold<fold>/` with `seq_eval_val/seq_predictions.csv` and `seq_eval_test/seq_predictions.csv`. For that layout:

```bash
python scripts/s3_train.py --config configs/ravdess.yaml --out-root runs/ensemble_demo --exp-name seed42 --seed 42 --cv --validation-only
python scripts/s3e_seq_eval.py --config configs/ravdess.yaml --exp-name ensemble_demo --seed 42 --fold 0 --split val --out-dir runs/ensemble_demo/seed42/fold0/seq_eval_val
python scripts/s3e_seq_eval.py --config configs/ravdess.yaml --exp-name ensemble_demo --seed 42 --fold 0 --split test --out-dir runs/ensemble_demo/seed42/fold0/seq_eval_test
```

Generate every requested fold/seed before calling the aggregation tools; inspect their `--help` options. Post-hoc calibration is fitted using validation predictions. The unit tests check ID alignment, evidence aggregation and calibration behavior. These tools do not change the default training objective.
